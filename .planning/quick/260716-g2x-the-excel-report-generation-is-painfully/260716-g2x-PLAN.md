<objective>
Speed up Excel (and shared PDF) report generation by implementing the two top-ranked low-risk optimizations from 260716-g2x-RESEARCH.md, exactly as locked by the user:

- R2: construct the calculator Result once per module in reports/base.py instead of three times, removing 4 of 6 full-MathResult deepcopies per freshly-calculated module (research H4).
- R1: memoize immutable reference lookups: the per-access ModuleType property query (research H3), the READY StatusType query inside per-module loops (research H1), and the hot IPCC reference getters in the deforestation/OLUC calculate paths (research H1).

R3 through R8 from the research ranking are explicitly OUT OF SCOPE.

Purpose: the report endpoint currently issues hundreds of identical ORM queries against reference tables that are immutable at runtime (loaded via load_reference_data), plus redundant deepcopies of full emission matrices. Both fixes are pure read-path changes that cannot alter computed numbers.

Output: one new module (djangoexact/api/reference_cache.py) plus surgical edits to djangoexact/api/reports/base.py, djangoexact/api/models.py, and djangoexact/api/calculators.py. No public API change, no calculation-result change, no fixture change.

Cache invalidation contract (accepted per locked decision): caches are per-gunicorn-worker process memos over runtime-immutable reference data; reloading reference data requires a process restart or calling clear_reference_caches(). This must be stated in docstrings. Residual known risk: tests that create their own reference rows mid-transaction could observe a stale memo across test cases in the same process; CI is the gate that surfaces this (no local DB exists), and clear_reference_caches() is the escape hatch if it does.
</objective>
