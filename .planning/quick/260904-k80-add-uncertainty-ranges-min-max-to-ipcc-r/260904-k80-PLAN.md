<objective>
Add nullable `_min`/`_max` uncertainty columns to 64 `ipcc` models and populate the committed fixtures from the 64 CSVs in `djangoexact/ipcc/data/uncertainties/`, joined on natural keys.

Purpose: the 2026-09-04 data drop carries uncertainty bounds next to every reference value. Storing them now unblocks a future uncertainty-propagation feature without touching today's numbers.
Output: one management command holding the whole mapping, 238 new nullable float columns, one migration, 64 patched fixtures plus the rebuilt combined fixture, a committed match report, and DB-free tests.

**Store only (D-02).** No calculator, `math_model`, report, or serializer change. The IPCC serializers use `fields = "__all__"`, so the columns surface in the API for free.

## Not tracer-shaped, and why

A tracer would ship one table end to end first. It cannot here: the mapping table is the single input to *both* the schema generation and the fixture writer, and the constraint is one migration for all 64 models. So the order is map (Task 1) → schema (Task 2) → write (Task 3). Task 1 still runs end to end across all 64 CSVs in dry-run and carries the real join, which is the only risky part; it just stops short of writing.

**Key derivation.** `key_columns = [c for c in header if map_to_field(c) is a concrete model field and map_to_field(c) is not a ranged base field and c != "id" and c != "unit" and not c.endswith("_unit")]`, preserving header order and first-occurrence only. Excluding bare `unit` as well as `*_unit` matters: `CoastalAGB.unit` and `agb_unit` disagree between CSV and fixture (`tC/ha` vs `tonnes d.m./ha`) and would zero out every match. Non-ranged numeric dimensions such as `from_year` and `forestmanagementbgb.threshold` stay in the key.

**Null tokens.** Treat `""`, `N/A`, `#N/A`, `NA`, `NULL` and `-` (case-insensitive, after strip) as "no value". `#N/A` appears in the organic-soil CSVs.

**Value coercion by field type.** Detect relations with `field.is_relation`, **not** by class name — `FiresCombustionFactor.land_use_type` and `IrrigationSystemData.irrigation_system_type` are `OneToOneField`, and a class-name check silently leaves them as strings and matches nothing. Integer fields via `int(float(raw))`, float fields via `float(raw)`, everything else as the stripped string.

**FK display-name resolution.** Build a name→pk map per related model from that model's committed fixture (via the manifest), keyed on `name` (falling back to `value`, then `label`), lowercased and stripped — matching must be case-insensitive, because `ipcc.livestockawms.csv` writes `East Asia And South-East Asia` where `api.IPCCRegion` stores `East Asia and South-East Asia`. Before the name lookup, try two pk-bearing display formats:
  - `^\w+ object \((\d+)\)$` — Django's default `__str__`; `ipcc.livestockmanureef.csv` writes `EmissionType object (3)` for all 27,720 rows
  - `^\((\d+)\)\s*(.+)$` — `(24) Forest Management (LUC)`, `(1) On-Site`; used by the organic-soil and peat-extraction CSVs
  In both cases take the captured integer as the pk and **assert it exists in the related model's fixture**; a pk not present in the fixture is an unresolved reference, not a match. This is the only pk-based resolution in the command and it resolves the *related* model, never the row's own `id` — the row's `id` column is always ignored (D-01).

**Matching.** Index the target fixture as `key_tuple -> [pk]`. Per CSV row: build the key, then classify into exactly one bucket:
  - `unresolved_fk` — any key component failed to resolve
  - `unmatched` — key absent from the fixture (a CSV row the fixtures lack; never insert it, D-01)
  - `ambiguous` — key hits 2+ fixture rows
  - `base_mismatch` — the row matched a unique fixture row, but for some ranged group the CSV's base column is numeric and disagrees with the fixture's stored base value beyond `math.isclose(rel_tol=1e-6, abs_tol=1e-9)`.   - `conflict` — a second CSV row landed on the same fixture pk with a *different* bound set. Skip it and record both values. Never last-write-wins (CONTEXT)
  - `written` — otherwise
