# Context — IPCC uncertainty ranges

User decisions below are **locked**. Do not revisit them.

## Source data

Delivered as `OneDrive_2026-09-04.zip`, copied into the repo at
`djangoexact/ipcc/data/uncertainties/` — **64 CSVs** plus one provenance `.docx`
(describes only how `ipcc.forestmanagementagb.csv` was built; not an
implementation instruction).

Every CSV maps to a model in `djangoexact/ipcc/models.py`. Each adds
`<field>_min` / `<field>_max` columns next to existing value columns:
**124 ranged field groups → 248 new nullable float columns across 64 models.**

The last CSV column is a header-only citation (`"Source: ..."`) with empty
values — it is metadata, not data. `N/A` and empty mean "no uncertainty known".

## D-01 — Uncertainty columns only, matched on natural keys

Add and populate `_min`/`_max` only. **Do not** change any existing base value,
unit, or row set, and do not insert rows the fixtures lack.

Rows are matched by **the combination of non-numeric dimension columns**
(climate, moisture, region/continent, country, land_use_type, forest_type,
livestock_*, etc.) — *not* by `id`.

This is not a preference, it is required: **CSV `id`s do not correspond to
fixture PKs.** Measured id-match rates include `foresttotalbiomass` 0/5792,
`perennialagb` 0/1632, `livestockawms` 0/7140, `forestmanagementbgb` 0/1086.
A natural-key join on `foresttotalbiomass` was prototyped and resolves every FK
name, joining 5632/5792 rows.

Join key derivation, per CSV:

    key = (CSV base columns ∩ model fields) − ranged fields − `*_unit` fields − `id`

`*_unit` is excluded deliberately: `forestmanagementagb.agb_unit` reads `tC/ha`
in the CSV but `tonnes d.m./ha` in the fixture, so including it would zero out
every match. Columns absent from the model (`summary`, `value (original)`,
`t_co2_eq`, `net_calorific_value`, `density` on EnergyDefaultEmissionFactor) are
excluded by the intersection.

Numeric dimension columns that are *not* ranged stay in the key — notably
`forestmanagementagb.from_year`.

Fixtures store FKs as integer PKs while CSVs store display names, so the join
needs name→PK maps built from `djangoexact/api/fixtures/*.json`
(climate, moisture, region, landusetype, country, …).

## D-02 — Store only

Model fields + migration + populated fixtures. The IPCC serializers use
`fields = "__all__"`, so the columns surface in the API with no serializer edit.
**No** calculator, `math_model`, or report changes. Uncertainty propagation
through calculations is explicitly a separate future feature.

## D-03 — Committed, re-runnable management command

`djangoexact/ipcc/management/commands/import_uncertainties.py`, reading the
committed CSVs and patching `ipcc/fixtures/*.json` plus
`api/fixtures/all_reference_data.json` by natural key. Must be idempotent so the
next data drop is a re-run, not a rewrite. Source CSVs are committed alongside.

## Known data quirks — all need explicit per-file handling

| CSV | Quirk |
|---|---|
| `FiresCombustionFactor.csv` | Both uncertainty columns collapsed into one quoted header cell `"value_min, value_max"` followed by an unnamed column. Data rows still carry two values — resolve **positionally**. |
| `ipcc.forestmanagementagb.csv` | `agb_min`/`agb_max`/`agb_growth_min`/`agb_growth_max` are **existing domain fields**, not uncertainty. The uncertainty columns are `agb_min_min`, `agb_max_max`, `agb_growth_min_min`, `agb_growth_max_max`. |
| `ipcc.atwood.csv` | Ranged columns are `area_2014_min`/`area_2014_max`; the model field is `area_2014_km2`. |
| `FMGData.csv` | The citation header sits in **column 0**, and that column holds the `id` values. |
| `IrrigationPressureRequirement.csv` | `bar_start`/`bar_end` appear twice; the second pair is stray `N/A`. Only `avg_pressure` and `head` are ranged. |
| `GrasslandAGB.csv` | `value` → model `ipcc.grasslandbiomass`, whose fields are `agb_t_dm_ha`/`agb_t_c_ha`/`bgb_t_dm_ha`/`bgb_t_c_ha`. Resolve which one `value` means before writing. |
| `ipcc.totalbiomassafterdefo_from_agb_bgb.csv` | `totalbiomass` → `totalbiomassafterdefo.value`; its `id` column is entirely blank. |

Two CSVs are encoded cp1252, not UTF-8: `InputEmissionFactor.csv` and
`IrrigationSystemData.csv`. Most others carry a UTF-8 BOM.

Filename → fixture aliases: `ipcc.forestmanagementbgb` →
`forestmanagementroottoshoot`, `ipcc.totalbiomassafterdefo_from_agb_bgb` →
`totalbiomassafterdefo`, `GrasslandAGB` → `grasslandbiomass`. Otherwise the stem
lowercased with any `ipcc.` prefix stripped.

## Ambiguity handling — required

Several CSVs carry more rows than the fixture has (`CoastalAGB` 60 vs 30,
`FLUData` 480 vs 336), so a natural key can collide. When two CSV rows map to
one fixture row with **different** uncertainty values, that is a conflict:
skip the row and report it. Never let last-write-win decide silently.

The command must print a per-table summary — rows matched, rows unmatched,
conflicts — and must fail loudly rather than write a partial result.
