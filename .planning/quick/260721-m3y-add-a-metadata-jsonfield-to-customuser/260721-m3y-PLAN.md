# Quick Task 260721-m3y: Add metadata JSONField to CustomUser

## Goal

Give the WebApp frontend a durable, free-form place to persist frontend-only
state (UI preferences, dismissed banners, last-used filters, etc.) against the
authenticated user's profile, without adding a new endpoint or table.

## Approach

Add a single `metadata` JSONField to `api.CustomUser` and expose it read + write
on the existing user profile serializers. No new views, URLs, or migrations
dependency chain changes beyond one additive migration.

Field definition (mirrors the existing `params = models.JSONField(default=dict)`
pattern at api/models.py:3522):

```python
metadata = models.JSONField(default=dict, blank=True)
```

`default=dict` (not `null=True`) so the field is always a JSON object, never
null — the frontend always gets `{}` to work with and never has to null-check.

## Deliberately NOT touched

- `accounts/serializers.py:UserSerializer` uses `fields = "__all__"` — it is the
  login-response serializer, so it auto-includes `metadata`. No edit needed.
- `UserSummarySerializer` (both api/ and accounts/) — these summarize OTHER users
  (project members). Personal frontend metadata must not leak there, so they are
  left untouched.
- No API contract break: all changes are additive.
