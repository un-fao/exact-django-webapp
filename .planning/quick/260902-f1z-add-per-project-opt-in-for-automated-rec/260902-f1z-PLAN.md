<objective>
Invert `ProjectNotificationPreference` from opt-out to opt-in so a project Admin receives the automated recap email only for projects they explicitly subscribed to, and gate subscription writes on project-admin.

Purpose: today the absence of a row means "send me everything". The user wants silence by default.
Output: one renamed field + migration 0294, a single recipient queryset replacing an N+1 loop, an admin gate on the preference write paths, and three DB-free tests.

BACKEND ONLY. The frontend lives in a separate repo. The rename is a breaking API change for it (`is_opted_out` -> `is_subscribed`, inverted polarity); no compatibility alias is planned — D-01 wipes the slate, so a client sending the old key is a client that should be updated.

Not a tracer-first plan: this is a field-polarity inversion inside a feature that is already wired end to end (model, migration, serializers, viewset, router, consumer all exist). A thin vertical slice would prove nothing new. Task 1 is nonetheless the full vertical cut — model through consumer in one commit — because a commit that renames the field without its consumers does not import.
