# Quick Task 260820-he5

A staff-only `/api/admin-scripts/fra-carbon-stock/` page that lists the FRA assessment
years from the metadata endpoint (latest pre-selected) and, on POST, replaces every
`ipcc.FRACarbonStock` row with data for the chosen year.

Both CONTEXT decisions are locked: `iso3` goes on `api.Country`, and the write is
replace-all inside one `transaction.atomic()`. Do not revisit either. The API contract in
CONTEXT.md was verified live — do not re-derive it.

## Facts established while planning (do not re-verify)

- `api.Country` has 256 rows; `name` is `unique=True`. Fixtures were regenerated from
  production on 2026-08-19 (260819-prd), so fixture names **are** the production names.
- `djangoexact/api/fixtures/country.json` and `.../all_reference_data.json` (63,867 objs,
  256 of them `api.country`) both round-trip **byte-identically** through
  `json.dumps(obj, indent=2, ensure_ascii=False) + "\n"`. Patching them in place therefore
  produces a diff containing only the added `iso3` lines. Verified.
- `djangoexact/scripts/ipcc_data/FRACarbonStock2025.csv` is UTF-8-with-BOM, 237 rows =
  **236 countries + a `© FRA 2026` footer row** (all four values empty). It is the
  ground-truth name list for the ~236 FRA countries.
- Case-insensitively, all 236 CSV names match a fixture `Country.name` except three:
  `Côte d'Ivoire` (fixture uses U+2019: `Côte d’Ivoire`),
  `Ascension, Saint Helena and Tristan da Cunha` (fixture: `Saint Helena`),
  `Naoero` (fixture: `Nauru`). Two others differ only in case
  (`Bonaire, Sint Eustatius and Saba`, `Falkland Islands (Malvinas)`) — compare
  case-insensitively.
- 28 of the 236 CSV rows have **all four values empty**, and the current importer creates
  all-null rows for them anyway. Mirror that: create a row for every returned country.
- No ISO3 data exists anywhere in the repo. `faker` (dev-only) covers just 167/256 names
  and misses China, USA, Russia, Viet Nam — unusable. `pycountry` is out (locked).
- Latest `api` migration is `0291`; `0290` is a deliberate numbering gap (260819-jfs).
  New migration is `0292`.
- Tests are Django `TestCase`, run with `python manage.py test <label>` from `djangoexact/`.
  Any test hitting the DB through the client needs
  `@override_settings(MIDDLEWARE=MIDDLEWARE_WITHOUT_DB_CLEANUP)` — see
  `admin_scripts/tests/test_views.py`.
- `requests==2.33.0` is a production dependency; the only existing outbound call
  (`accounts/firebase_auth.py:113`) passes an explicit `timeout=`.

## Task 1 — `Country.iso3`: field, mapping data, migration, fixtures

**Files:** `djangoexact/api/models.py`, `djangoexact/api/data/country_iso3.csv` (new),
`djangoexact/api/migrations/0292_country_iso3.py` (new),
`djangoexact/api/fixtures/country.json`, `djangoexact/api/fixtures/all_reference_data.json`

**Action:**

1. Add to `api.Country`, declared immediately after `name` (so a later
   `dump_reference_data` run emits fields in the same order as the patched fixtures):
   `iso3 = models.CharField(max_length=3, null=True, blank=True, unique=True)`.
   `null=True` (never `""`) is what lets the unmapped countries coexist under the unique
   constraint — Postgres permits repeated NULLs. `unique=True` already creates the index;
   do not add `db_index=True`.

2. Create `djangoexact/api/data/country_iso3.csv`, header `iso3,name`, UTF-8, one row per
   ISO-3166-1 alpha-3 code. The `name` column must be **verbatim** a `Country.name` from
   `country.json` (copy the strings out of the fixture; do not retype accented or
   curly-apostrophe names). Keyed by ISO3, so one code can never land on two countries.

   Expect ~248 rows. These 8 fixture names have no alpha-3 code and are deliberately left
   out — none of them appear in FRA's country list, so none affect the import:
   `Azores (Portugal)`, `Canary Islands`, `Madeira Islands`, `Channel Islands`,
   `Southern Africa`, `Sark`, `Kosovo`, and `Taiwan ` (trailing space; assign `TWN` to
   `Taiwan (Chinese Taipei)` instead, and note FRA reports no Taiwan row at all).

3. Add migration `0292_country_iso3.py`: `AddField`, then a `RunPython` that reads the CSV
   with `Path(__file__).resolve().parents[1] / "data" / "country_iso3.csv"` (open with
   `encoding="utf-8"`), and for each row runs
   `Country.objects.filter(name=row["name"]).update(iso3=row["iso3"])` via
   `apps.get_model("api", "Country")`. Exact name match, not `iexact` — the CSV names are
   copied from the fixture. Reverse operation is `migrations.RunPython.noop`.

4. Patch both fixtures in place with a throwaway script (do **not** commit the script, and
   do **not** run `dump_reference_data` — that would need a fully-seeded DB and risks
   touching unrelated rows): load each JSON, and for every object with
   `model == "api.country"` rebuild `fields` as `{"name": ..., "iso3": <code or None>, ...rest}`
   so `iso3` sits right after `name`; write back with
   `json.dumps(data, indent=2, ensure_ascii=False) + "\n"`. Confirm with `git diff --stat`
   that only `iso3` lines were added.

**Verify:**

```bash
cd djangoexact && python -c "
import csv, io, json, re
m = list(csv.DictReader(io.open('api/data/country_iso3.csv', encoding='utf-8')))
names = {c['fields']['name'] for c in json.load(io.open('api/fixtures/country.json', encoding='utf-8'))}
assert all(re.fullmatch(r'[A-Z]{3}', r['iso3']) for r in m), 'bad iso3 format'
assert len({r['iso3'] for r in m}) == len(m), 'duplicate iso3'
assert len({r['name'] for r in m}) == len(m), 'duplicate name'
assert len(m) >= 245, len(m)
missing = [r['name'] for r in m if r['name'] not in names]
assert not missing, missing
print('mapping ok:', len(m), 'codes')
"
cd djangoexact && python manage.py makemigrations api --check --dry-run
```

**Done:** `country_iso3.csv` passes the checks above, `makemigrations --check` reports no
pending changes (0292 covers the field), and `git diff` on the two fixtures shows only
added `iso3` lines.

## Task 2 — FRA client + admin script page

**Files:** `djangoexact/admin_scripts/fra_carbon_stock.py` (new),
`djangoexact/admin_scripts/views.py`, `djangoexact/admin_scripts/urls.py`,
`djangoexact/admin_scripts/templates/admin_scripts/scripts/fra_carbon_stock.html` (new)

**Action:**

`fra_carbon_stock.py` — a module, not view-embedded code, matching the app's existing
`catalog.py` / `gap_detector.py` / `scenario_utils.py` split, and so the parsing and the
DB write are testable without HTTP:

- Constants: base `https://fra-data.fao.org/api/explorer`, `HEADERS = {"User-Agent": "Mozilla/5.0"}`
  (Cloudflare 403s without it — mandatory), `TIMEOUT = 120`, and
  `VARIABLES = {"carbon_forest_above_ground": "agb", "carbon_forest_below_ground": "bgb",
  "carbon_forest_deadwood": "deadwood", "carbon_forest_litter": "litter"}`.
- `fetch_years()` → GET `/sections/metadata` with params
  `assessmentName=fra, countryIso=WO, cycleName=2025, sectionNames[]=carbonStock`;
  return `payload["carbonStock"]["dimensions"]` names sorted ascending by `int()`.
- `fetch_data(year, isos)` → GET `/data` with `assessmentName=fra`, `columns[]=[year]`,
  `countryISOs[]=isos`, `tableNames[]=["carbonStockAvg"]`, `variables[]=list(VARIABLES)`.
  Pass repeated params as lists through `params=` so `requests` does the encoding; never
  build the query string by hand. Both helpers call `raise_for_status()`.
- `parse_payload(payload, year)` → `{iso: {"agb": float|None, ...}}` walking
  `payload["fra"][year][iso]["carbonStockAvg"][year][variable]["raw"]` with `.get()` at
  every level. `raw` is a string or null: `None`/`""` → `None`, else `float(raw)`. Entries
  that also carry `"calculated": true` are treated identically — read `raw` and ignore the
  rest.
- `replace_carbon_stock(year, by_iso)` → build `{iso3: Country}` from
  `Country.objects.exclude(iso3__isnull=True)`, then inside a single `transaction.atomic()`
  delete **all** `FRACarbonStock` rows and `bulk_create` one row per mapped ISO with
  `year=int(year)` and the four fields. Create a row even when all four values are `None` —
  that is what the CSV importer does today for 28 countries, and changing it would flip
  `calculators.py:7289` from `agb=0` to a raised `ValueError`. Leave
  `carbon_stock_biomass_total` and `carbon_stock_total` null. Return
  `{"year": int(year), "deleted": n, "created": n, "unmapped": sorted(set(by_iso) - set(countries))}`.

`views.py` — add `fra_carbon_stock(request)` next to `example_script`, same decorator pair
`@login_required(login_url="/admin/login/")` + `@staff_required`, and add a `SCRIPTS` entry
`{"name": "Import FRA Carbon Stock", "url": "fra-carbon-stock", "description": "Replace all FRA carbon stock rows with data for a chosen FRA assessment year."}`.
Behaviour:

- Always `fetch_years()` first; on exception render with an error and an empty year list.
- `selected_year` defaults to `max(years, key=int)` (latest pre-selected).
- Write only on `request.method == "POST"`. Read `request.POST.get("year", "")` and reject
  it unless it is in the freshly fetched `years` list — this is the trust boundary; the
  value goes into an outbound URL. On rejection set an error and do not touch the DB.
- On a valid year: `isos = list(Country.objects.exclude(iso3__isnull=True).values_list("iso3", flat=True))`,
  then `replace_carbon_stock(year, parse_payload(fetch_data(year, isos), year))`. Catch
  `requests.RequestException` and `ValueError` into the page `error` — an admin page must
  not 500 on an upstream hiccup.
- Report the returned counts and the `unmapped` ISO list in the context (mirrors the
  `missing_countries` print the ipcc_dump function does today).

`urls.py` — `path("fra-carbon-stock/", views.fra_carbon_stock, name="fra-carbon-stock")`.

Template — copy `example_script.html`'s shape (extends `admin_scripts/base.html`, back
link, the `{# nosemgrep: python.django.security.django-no-csrf-token... #}` comment above
the `<form method="post">`, `{% csrf_token %}` inside). Replace the text input with a
`<select name="year">` marking `selected` on `selected_year`, an
`onsubmit="return confirm('This deletes every FRA carbon stock row and re-imports the selected year. Continue?')"`
on the form because the action is destructive, and a result block printing
deleted/created/unmapped.

**Verify:**

```bash
cd djangoexact && python manage.py check
```

**Done:** `/api/admin-scripts/` lists "Import FRA Carbon Stock"; the page GETs a year
dropdown with the latest year pre-selected and writes nothing; POST with a year not in the
metadata list is rejected; a successful POST leaves exactly one `FRACarbonStock` year in
the table.

## Task 3 — Tests

**Files:** `djangoexact/admin_scripts/tests/test_fra_carbon_stock.py` (new)

**Action:** four `TestCase` classes, no network — patch
`admin_scripts.views.fetch_years` / `fetch_data` (or the module attributes) with
`unittest.mock.patch`. Reuse `MIDDLEWARE_WITHOUT_DB_CLEANUP` from `tests/test_views.py`
for the view class.

1. `Iso3MappingTest` — the offline correctness gate on the hand-authored mapping. Assert
   the four structural checks from Task 1's verify block, plus: every country name in
   `scripts/ipcc_data/FRACarbonStock2025.csv` (read with `encoding="utf-8-sig"`, drop the
   `© FRA 2026` footer, apply the three known aliases `Ascension, Saint Helena and Tristan da Cunha`
   → `Saint Helena`, `Naoero` → `Nauru`, `Côte d'Ivoire` → `Côte d’Ivoire`) has an entry in
   `country_iso3.csv`, compared **case-insensitively**; plus a hard-coded spot-check dict of
   at least 15 pairs covering the codes that are easy to get wrong —
   `AFG/Afghanistan, DZA/Algeria, CIV/Côte d’Ivoire, PRK/Democratic People's Republic Of Korea,
   KOR/Republic Of Korea, RUS/Russian Federation, VNM/Viet Nam, USA/United States Of America,
   GBR/United Kingdom Of Great Britain And Northern Ireland, TUR/Türkiye, SWZ/Eswatini,
   CPV/Cabo Verde, TLS/Timor-Leste, CZE/Czechia, HKG/China, Hong Kong SAR, MAC/China, Macao SAR`.
2. `Iso3FixtureTest` — every `api.country` row in `country.json` whose name is in the
   mapping carries the matching `iso3`, and the rest carry `None`.
3. `ParsePayloadTest` — a hand-built payload exercising: a full four-variable country, a
   country whose `deadwood.raw` is `null`, a country carrying `"calculated": true`, and a
   country missing a variable key entirely. Assert floats, `None`s, and no `KeyError`.
4. `ReplaceCarbonStockTest` — create two `Country` rows with `iso3` and one without;
   pre-create a `FRACarbonStock` row for a **different** year and a different country;
   run `replace_carbon_stock("2020", ...)` with a payload containing one unknown ISO.
   Assert: the stale row is gone, one row per mapped country, `year == 2020`, values match,
   the unknown ISO is returned in `unmapped`, and — the invariant `calculators.py:7289`
   depends on — `FRACarbonStock.objects.values_list("year", flat=True).distinct().count() == 1`.
5. `FraCarbonStockViewTest` — anonymous GET redirects to `/admin/login/`; non-staff GET is
   403; staff GET with `fetch_years` patched to `["1990","2020","2025"]` returns 200 and
   marks 2025 selected; staff POST with `year=1999` leaves `FRACarbonStock` untouched and
   shows an error; staff POST with `year=2025` and both fetchers patched creates rows.
